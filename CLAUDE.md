# TripleCrown Project Documentation

This document serves as a persistent context guide for AI collaborators working on the **TripleCrown** project. It outlines the architecture, technical stack, and design principles to ensure consistency across the codebase.

---

## Project Overview
**TripleCrown** is a high-performance motorsport dashboard designed to provide real-time race schedules and the latest paddock news across multiple racing series (F1, WEC, MotoGP, IndyCar, etc.). The application prioritizes a "racing first" aesthetic with a focus on typography, high-contrast palettes, and responsive timeline-based scheduling.

**Core User Flow:**
1.  **Home:** View upcoming race countdowns and a snapshot of latest news.
2.  **News:** Browse and filter paddock news fetched from a dedicated API proxy.
3.  **Schedule:** Interact with a season-wide timeline to view specific event sessions (Practice, Qualifying, Race) with local time conversion and broadcasting links.

## Workflow & Rules

### Core Commands
The project is a static site. Use any local server for development:
- **Local Dev:** `npx serve .` or VS Code Live Server.
- **Production:** No build step required; ensure `assets/` and `data/` are correctly synced.

### Coding Standards
1.  **Vanilla JS over Frameworks:** Do not introduce React/Vue/Svelte unless requested. Use template literals for DOM generation in `main.js`.
2.  **Naming Conventions:**
    - **CSS:** Use descriptive classes prefixed with `rm-` for project-specific components (e.g., `.rm-nav`, `.rm-section`).
    - **JS:** Use `UPPER_SNAKE_CASE` for global state/constants (e.g., `SCHEDULE_DATA`, `NEWS_CATEGORIES`) and `camelCase` for functions.
3.  **Bootstrap Interop:** Leverage Bootstrap's grid and utilities (`d-flex`, `mt-5`, `container`) but override styling using `:root` variables in `style.css`.
4.  **Date Handling:** All racing schedule data follows ISO 8601 formatting. Localize formatting using `toLocaleDateString('en-GB')` and `Space Mono` for alignment.

### Documentation & Commits
- **AI Reference-Free:** Do not include comments like "Generated by AI" or "@model-instruction".
- **Concise Commits:** Use imperative mood (e.g., "Add WEC 2026 schedule", "Fix timeline scroll-spy").

## Architecture

```text
TripleCrown/
├── assets/
│   ├── css/
│   │   └── style.css      # Core theme, variables, and component overrides
│   └── js/
│       └── main.js       # App logic: Fetching, Scheduling, Rendering
├── data/
│   ├── schedule/
│   │   └── {year}/        # JSON race calendars (f1_2026.json, etc.)
│   └── news/              # (Reserved for local news datasets)
├── index.html             # Main entry point with section-based navigation
└── .gitignore             # Standard git exclusions
```

-   **`main.js`**: Handles global state (`activeYear`, `activeSeries`), data fetching for 10+ racing series, and dynamic DOM injection for the news/schedule grids.
-   **`style.css`**: Contains a robust `:root` system for Light/Dark mode and "Racing Stripe" accents.

## Lessons Learned & "Gotchas"

-   **Locked Sticky Headers:** The schedule timeline uses a "Sticky Sentinel" pattern to trigger visual changes (background blur/shadow) when the filters hit the top of the viewport.
-   **Chronological vs Grouped:** The app supports two views for the schedule. Switching requires re-rendering the session blocks from a flattened array of event data.
-   **TBC Times:** Always check for `TBC` in JSON `start_time`. Default to "00:00:00" or a fallback date object to prevent `Invalid Date` errors in JS.
-   **Responsive Overlays:** The `loadingOverlay` and `errorContainer` must be toggled via `d-none` to ensure clean transitions between API states.
